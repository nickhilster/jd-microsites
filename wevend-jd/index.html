The agent environment

Owned, not inherited.

SpecRequirements become instructions, acceptance criteria and test cases an agent can build from — pressure-tested before any code exists.
InstructEvery repo carries its instruction file: architecture, standards, standing rules. Persistent per-project agent sessions reuse context instead of re-buying it.
ConnectMCP servers built and maintained by me; tool access scoped read-only by default; secrets in secure storage, fetched per session, never in a repo.
DirectSmall steps, easy to review and roll back. Branches, worktrees and pull requests across a five-machine fleet.
VerifyTests, CI, blob-hash checks on every push, and live checks against the served artifact. An agent report is a claim until the artifact confirms it.
Proof of the hygiene standard: before one of my repositories went public in November 2026, I scanned its full history for credential-shaped values, rotated the live access token on the server, scrubbed the committed values — and only then flipped it public. In that order.
Verification

The numbers behind the practice.

Tests

Suites as acceptance gates

LTB Buddy portal-assistant suites green at 55 of 55; FileBuddy at 61 of 63 with 2 Windows-only skips; NikBot guarded by a production smoke test after every change.

Pushes

Blob-for-blob, every time

Every push to a deployment-linked repository is verified by comparing git blob hashes against the tested local tree. A green build is not proof; the served page is.

Review

Diffs read, not waved through

Agent output is reviewed line by line where it matters, and logic errors that pass the tests are the specific thing I hunt. Small bugs I fix directly; the rest goes back with a sharper spec.
