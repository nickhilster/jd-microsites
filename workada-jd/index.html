How I build a task

Three principles, learned from grading real agent work

The same discipline I use to run my own multi-agent operation at TeamBotics.

01

Start from real work

Every task is seeded from something that actually broke in practice — a pipeline that silently dropped structure, a harness that trusted its own success report. Synthetic puzzles test puzzles. Real work tests agents.

02

Build the reference first

A task without a reference solution is an opinion. I solve every task myself, in the same environment the agent receives, before I write a single check — so the standard is demonstrated, not asserted.

03

Grade the artifact, not the report

An agent's summary is evidence of what it reported, not of what happened. My checks inspect the final state — files, outputs, structure — and the agent's prose earns nothing.

4Age and CAF

4Age is my human-approved protocol for agent-to-agent work, running across a live multi-agent mesh. CAF — Capability Awareness Failure — is the failure taxonomy I coined for agents that fail to use capabilities they already have. Method

How a problem from my practice becomes a Task

Brief→ Environment→ Reference solution→ Automated checks→ Adversarial pass

The brief states the goal and the constraints and nothing else — instructions written to leave no room for misreading. The environment ships with the files and tools the work needs. The reference solution proves the task is solvable as specified. The checks grade the final state. Then I run the strongest agent I have against it and keep the tasks it still gets wrong.

First tasks

Three tasks I would bring first

Each is drawn from work I have already done, with the failure mode observed firsthand.

Software · Data

The silent formatting pipeline

From the LTB portal audit: migrate structured filings through a three-stage pipeline where each stage quietly loses structure — line breaks, punctuation, paragraphing. The agent's output looks clean and reads wrong. Checks compare the final artifacts field by field against the source.

ML · Evaluation

The confident report

From the harness bake-off: a multi-step build task in an environment containing a planted discrepancy between what can be reported and what is actually true in the artifacts. The agent that narrates success without verifying its own output fails; the checks grade only the artifacts.

Research · Verification

The claim that needs a source

From Claim Checker: decompose a public claim into atomic units and verify each one against primary sources. Partial credit per atom; detecting the contradicted atom — the one the source itself disproves — is where today's agents are weakest.
